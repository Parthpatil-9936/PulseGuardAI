## Executive Summary

This report documents the design, hyperparameters, data ingestion pipeline, multi-seed training, calibration methodology, and empirical verification results for the **PulseGuard-AI 1D-CNN Autoencoder**. The model processes high-frequency multi-vital ICU telemetry generated by `simulator/generator.py`, scores multi-vital physiological anomalies in sub-5ms latency, and feeds into the 3-Tier Alert Cascade triage engine.

## 1. Raw Telemetry Input Pipeline (`generator.py` Integration)

### 1.1 Ingestion Contract & JSON Payloads
The model receives continuous 10 Hz telemetry ticks produced by `simulator/generator.py` (matching Section 3.1 specs). A raw tick payload has the following exact format:

```json
{
  "bed_id": "bed-01",
  "ts": "2026-09-25T18:38:37.123Z",
  "hr": 78,
  "spo2": 98,
  "bp_sys": 120,
  "bp_dia": 80,
  "ecg_lead_ok": true,
  "seq": 10452
}
```

### 1.2 End-to-End Data Transformation Flow

```
[ generator.py JSON Tick ]
         │
         ▼
[ Pydantic TelemetryTick ]  ---> Validates bounds (HR 0-300, SpO2 0-100, BP 0-300, ^bed-(0[1-9]|10)$)
         │
         ▼
[ Ingestion Service ]      ---> Reorders monotonic `seq`, forward-fills missing vitals, checks SQI & stuck sensors
         │
         ▼
[ TelemetryRingBuffer ]    ---> Buffers last 100 samples per bed into a (3, 100) raw float32 array
         │
         ▼
[ scale_raw_window() ]     ---> Min-Max scales raw array to [0.0, 1.0] range
         │
         ▼
[ PyTorch Autoencoder ]    ---> Input Tensor: (batch_size, 3, 100) -> Reconstructed Tensor: (batch_size, 3, 100)
         │
         ▼
[ Compute Per-Channel MSE] ---> Calculates separate MSE for HR, SpO2, BP_sys
         │
         ▼
[ Triage Decision Engine ] ---> Evaluates Hard Limits + ML Score + Hysteresis -> Outputs TriageDecision JSON
```

## 2. 1D-CNN Autoencoder Architecture

The model (`TelemetryAutoencoder`) is a lightweight 1D Convolutional Autoencoder designed for ultra-low latency (<5ms) edge execution.

### 2.1 Model Architecture Summary

| Layer Type | Input Shape | Output Shape | Kernel / Stride / Pad | Activation / Norm |
|---|---|---|---|---|
| **Input** | `(B, 3, 100)` | `(B, 3, 100)` | — | Scaled $[0.0, 1.0]$ |
| **Encoder Conv 1** | `(B, 3, 100)` | `(B, 16, 50)` | $K=3, S=2, P=1$ | BatchNorm1d + LeakyReLU(0.2) |
| **Encoder Conv 2** | `(B, 16, 50)` | `(B, 32, 25)` | $K=3, S=2, P=1$ | BatchNorm1d + LeakyReLU(0.2) |
| **Encoder Conv 3** | `(B, 32, 25)` | `(B, 32, 5)` | $K=5, S=5, P=0$ | BatchNorm1d + LeakyReLU(0.2) |
| **Bottleneck FC** | `(B, 160)` | `(B, 16)` | Linear ($160 \to 16$) | Latent Space ($Z \in \mathbb{R}^{16}$) |
| **Decoder FC** | `(B, 16)` | `(B, 160)` | Linear ($16 \to 160$) | LeakyReLU(0.2) |
| **Decoder ConvT 1**| `(B, 32, 5)` | `(B, 32, 25)` | $K=5, S=5, P=0$ | BatchNorm1d + LeakyReLU(0.2) |
| **Decoder ConvT 2**| `(B, 32, 25)` | `(B, 16, 50)` | $K=3, S=2, P=1, OP=1$ | BatchNorm1d + LeakyReLU(0.2) |
| **Decoder ConvT 3**| `(B, 16, 50)` | `(B, 3, 100)` | $K=3, S=2, P=1, OP=1$ | **Sigmoid()** |

### 2.2 Model Parameter Statistics
- **Total Parameters:** 19,211 parameters (~77 KB in memory)
- **Inference Latency:** < 1.2 ms on CPU
- **Input Scaling Bounds:**
  - `HR`: $[0.0, 300.0]$ bpm $\to [0.0, 1.0]$
  - `SpO2`: $[0.0, 100.0]$ % $\to [0.0, 1.0]$
  - `BP_sys`: $[0.0, 300.0]$ mmHg $\to [0.0, 1.0]$

## 3. Training Setup & Hyperparameters

To prevent mode collapse and domain over-fitting, the autoencoder was trained on **combined multi-seed healthy datasets**:

### 3.1 Training Hyperparameters

| Hyperparameter | Value | Description |
|---|---|---|
| **Optimizer** | Adam | Adaptive moment estimation |
| **Learning Rate ($\eta$)** | `1e-3` | Initial learning rate |
| **Weight Decay** | `1e-5` | $L_2$ regularization |
| **Loss Function** | MSE | Mean Squared Error |
| **Batch Size** | 64 | Window mini-batch size |
| **Epochs** | 15 | Total training epochs |
| **Training Dataset Seeds** | `[41, 42, 43]` | Multi-realization synthetic healthy seeds |
| **Total Training Windows** | 1,530 windows | 153,000 individual 10 Hz samples |
